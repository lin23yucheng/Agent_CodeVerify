# AI 辅助代码静态审查

根据测试用例静态审查开发仓库代码，判断用例意图是否已由代码实现，并生成带判断依据的 CSV 结果。审查由 AI 编码助手按照仓库约定执行，不运行被审查项目或测试。

## 项目结构

- `config/review-config.json`：开发仓库、默认分支、用例匹配规则和结果列配置。
- `prompts/static-code-review.md`：审查步骤、状态定义和单条用例判定原则。
- `testcase/`：待审查的 CSV 用例。
- `results/`：生成的审查结果，不覆盖原始用例文件。
- `AGENTS.md`：AI 编码助手在本项目中的执行约定。

## 使用方法

1. 在 `config/review-config.json` 中配置有读取权限的开发仓库地址和默认分支，并确认用例文件匹配规则及输出配置。
2. 将待审查的 CSV 放入 `testcase/`，确保表头包含用例所属模块、名称、前置条件、步骤和预期结果等信息。
3. 在本项目中向 AI 编码助手提出“根据用例审查代码”。如需审查其他仓库或代码版本，可在请求中明确指定仓库、分支或提交。
4. 查看 `results/` 下生成的结果 CSV。文件名由原用例文件名和配置的后缀组成，原有内容保留，并追加实现结果和说明解释列。

审查过程会记录实际审查的提交 SHA。说明解释列包含判断依据及开发仓库中的相对路径和行号。

## 实现状态

- `已实现`：代码逻辑覆盖用例意图，用户可观察到的结果符合预期。
- `未实现`：相关入口和调用路径中未发现用例要求的功能。
- `实现不符合用例`：存在相关功能，但规则、边界或结果与用例要求不一致。
- `静态无法判断`：代码不足以确认用例行为，且判断确实依赖无法从代码确定的运行时结果或外部信息。

测试数据由测试环境和用例前置条件提供。审查应检查代码对用例所述数据状态的处理，不因无法访问当前数据库而将结论标为静态无法判断。

## 审查边界

审查只阅读和分析开发仓库源代码及用例，不启动服务、不调用接口、不执行测试或生成的脚本。结果是基于指定提交的静态代码判断，不代表运行时测试通过。
